# art2real

**임의의 이미지로부터 CAD 코드를 만드는 연구 저장소.**

그림 한 장(도면, 원화, 사진)을 받아서, 사람이 고쳐 쓸 수 있는 CAD 코드(CadQuery)를 내놓는 것이 목표입니다. 메시를 바로 생성하지 않고, 부품을 이루는 덩어리와 그 치수·자리를 숫자로 뽑아 코드로 짓습니다.

- 판(실험) 목록과 보고서: https://sigongjoa.github.io/art2real/
- 판마다 하나씩 열리는 이슈: https://github.com/sigongjoa/art2real/issues?q=is%3Aissue

## 지금 하는 일

중간 단계로, 생성한 부품의 3면도(위·앞·옆 선화)를 입력으로 씁니다.

```
3면도 세 장 (128×128 선화 · 실선 + 숨은선)
  → CNN 인코더 (그림마다 8×8 조각 토큰)
  → 트랜스포머 디코더 (칸 6 개 = 덩어리 최대 6 개)
  → 덩어리 사양 (종류 · 치수 · 축 · 자리 · 구멍 · 필렛)
  → CadQuery 코드 → 메시
```

학습 데이터는 덩어리 1~6 개를 붙인 생성 부품 약 12,000 개입니다. 채점은 3/4 시점 실루엣 IoU 로 합니다.

## 지금까지 알아낸 것

| | 결과 |
|---|---|
| 그림 인코더 | 얼린 EmbeddingGemma 2 벡터는 덩어리 자리 정보를 버린다(선형 탐침이 평균 수준). CNN 조각 토큰으로 바꾸자 처음 보는 부품 IoU 0.633 → 0.737 |
| 머리 구조 | MLP 와 트랜스포머가 같은 점수(0.638 대 0.633). 병목은 머리가 아니었다 |
| CNN 특징 | 곡선 · 선이 만나는 곳 · 실선과 숨은선이 겹친 곳을 잘 가려내지 못한다. 어텐션은 오히려 그런 곳을 피하고 빈 바탕에 몰린다(접합 0.23 배 · 빈칸 1.55 배) |
| 칸 짝 | 덩어리를 부피 순으로 칸에 고정하면 칸들이 비슷해진다. 가장 가까운 칸끼리 짝지으면 자리 오차 0.27 → 0.17 |
| 과적합 | 60 에폭에서 시험 loss 가 다시 오르고, CNN 의 곡률 특징도 12 에폭보다 나빠진다 |

열린 문제와 근거 숫자는 판 목록 페이지의 연구 트리에 모아 둡니다.

## 연구는 이렇게 돕니다 — 하네스

판 하나는 **명제 하나**(틀릴 수 있는 문장)를 시험합니다. 하네스(`하네스/`)가 판을 처음부터 끝까지 끌고 갑니다.

1. **관문**: 명제 · 판정 기준 · 같은 에폭의 대조가 적혀 있고, 판 설정이 실행 전에 커밋돼 있어야 시작합니다. 바탕 설정에서 손잡이를 둘 이상 바꾼 비교 판은 거부합니다.
2. **연기 판**: 첫 loss · 배치 하나 외우기 · GPU 메모리를 먼저 확인합니다.
3. **학습**: 부품을 이름으로 골라 조립하고(인코더 · 짝 방식 등), 에폭마다 체크포인트를 남깁니다.
4. **점검**: 학습 곡선, 층별 어텐션, 합성 그림 탐침, 실제 도면의 특징(곡선 · 접합 · 겹친 곳)을 판마다 같은 꼴로 잽니다.
5. **판정**: 미리 적은 기준으로 통과 · 실패를 계산합니다.
6. **기록**: 보고서(HTML · PNG), 결과 표 한 줄, 커밋, 이 저장소로 푸시, 이슈, 쇼츠 대본과 영상까지 만듭니다.

```bash
# Windows · Python 3.11 venv (torch cu124 · cadquery · open3d · hydra-core)
python 하네스/하네스.py --config-name 판_127재현
```

판 설정은 `하네스/conf/바탕.yaml` 을 받고 바꿀 것만 적습니다. 예시는 `하네스/conf/판_127재현.yaml` 입니다.
