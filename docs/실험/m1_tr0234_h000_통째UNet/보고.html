한 줄로

물음: 그림 한 장(+ 시점)을 받아 3 면도 6 칸을 통째로 내는 U-Net 꼴 망은 시험 3 면도 선 F 가 tr184(한 장 직접 0.608)를 넘나?

답: 못 넘었다(결정 표 「다」). 시험 0.445 로 tr184 보다 0.16 낮고, 입력을 아예 안 보는 평균 3 면도(바닥 0.459)보다도 낮다. 망은 3 면도를 그리지 않고 입력 그림의 선을 세 칸에 베꼈다(베끼기 F 0.76 · 정답 3 면도는 0.46).

왜 이 판을 했나

여러 장 길은 tr233 에서 0.872(+27 %)에 멈췄다. 사용자 계획은 원화 한 장 → 3 면도 U-Net 이고, 11-19 에 「통째 U-Net」 을 직접 골랐다(시점 바꾸는 U-Net · 정면만 U-Net 대신).

바꾼 것 하나

출력을 그 시점 지도 6 장에서 3 면도 6 칸으로 바꿨다. 망은 tr226 꼴(얼린 DINOv2 16² + DA + 입력에서 64² · 128² 로 건너뛰는 길)에 시점 입력(FiLM)을 더했다. 정답은 tr184 의 부품별 3 면도(tr227 정답과 F 1.0)다. 멈춤은 검증 3 면도로 했다(11,000 스텝).

왜 이렇게 나왔나

확인한 것

  • 예측 3 면도 칸이 입력 시점 선 지도와 0.76 닮았다. 정답 3 면도는 0.46 이다. 망은 입력 선을 세 칸에 옮겨 그렸다(그림: 비스듬한 상자 · 원통이 위 · 앞 · 옆 모두에).
  • 건너뛰는 길만 끈 tr235 는 베끼기가 0.36 으로 줄었지만 모든 입력에 같은 그림을 냈다(다양성 0.003 · 무너짐).
  • 검증 3 면도는 4,000 스텝 뒤로 0.37 ~ 0.44 를 오르내렸다.

짐작 (아직 확인 안 함)

  • 한 장에서 다른 시점 선의 자리를 통째로 맞히는 일을 이 꼴(화소가 화소로 가는 디코더)은 못 배운다. 건너뛰는 길이 있으면 베끼고, 없으면 평균으로 숨는다. tr184(질의 토큰으로 3 면도를 짓는 디코더)가 0.608 로 더 높은 것과 맞는다.

배운 것과 다음

통째 U-Net 은 한 장 → 3 면도에서 입력 선 베끼기나 평균 그림으로 빠져, 입력을 안 보는 바닥도 못 넘는다.

  1. 결정 표 「다」: 시점 바꾸는 U-Net(한 장 + 보고 싶은 축 시점 → 그 시점 선 지도 → tr233 그리기)을 사용자와 다시 정한다.
  2. 비교 기준: 바닥 0.459 · tr184 0.608 · 여러 장 길 0.872.
