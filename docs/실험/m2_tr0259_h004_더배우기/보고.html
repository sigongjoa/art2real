분석

한 줄로

물음: 새 구조 m2 를 30 바퀴에서 이어 100 바퀴까지 더 배우면, 정답 view 로 짓는 CAD code 모양 맞음이 오르나?

답: 오르지 않는다(둘 다 보류). 학습 손실은 5.08 → 2.76 으로 절반 가까이 줄었지만 시험 모양 맞음은 0.09 → 0.10 에 머물렀다. 줄어든 손실은 종류 · 축 · 몸 수 같은 고르기 몫이었고(배운 부품 0.99), 치수와 자리는 배운 부품에서도 못 맞혔다. 손잡이는 배우는 양이 아니라 비스듬한 view 에서 숫자를 읽는 능력이다.

왜 이 실험을 했나

m2-tr258 에서 새 구조 m2 는 30 바퀴에 시험 0.09, 배운 부품 0.04 였고 손실이 끝까지 내려가고 있었다. 사용자가 「체크포인트 이후에 길게 해야 하지 않을까」 라고 했다. 덜 배운 탓인지 확인하려고 같은 설정으로 더 배웠다.

바꾼 것 하나

배우는 양. tr258 30 바퀴 무게에서 31 ~ 100 바퀴를 이어 배웠다(학습률 · 데이터 · 망 그대로 · 옵티마이저는 새로). 50 · 70 · 100 바퀴에서 같은 시험으로 CAD 를 지었다.

왜 이렇게 나왔나

확인한 것

  • 시험 모양 맞음 10 · 30 · 50 · 70 · 100 바퀴 = 0.08 · 0.09 · 0.11 · 0.10 · 0.10. 표면 거리 중앙은 0.24 → 0.20 으로 아주 천천히 준다(모양 맞음 기준은 0.05).
  • 칸별(30 → 100 바퀴): 배운 부품 종류 0.83 → 0.997 · 축 0.87 → 0.997 · 몸 수 0.80 → 0.99 — 고르기는 다 외웠다. 치수 오차 10.7 → 10.0 % · 자리 3 % 넘게 틀린 몸 90 → 87 % — 숫자는 거의 그대로다.
  • 시험 부품은 종류 0.43 · 축 0.58 · 몸 수 0.59 로 배운 부품과 차이가 크다(고르기는 외움에 가깝다).
  • 3면도 입력(tr182)에서는 자리 3 % 넘는 몸이 40 ~ 58 %, 치수 오차 6 % 였다. 아무 각도 view 에서 숫자가 훨씬 나쁘다.
  • 각도를 20° · 45° 틀려도 0.10 · 0.09 로 거의 같다 — 망이 여전히 각도를 거의 쓰지 않는다.

짐작 (아직 확인 안 함)

  • 3면도는 축에 맞춘 그림이라 치수 · 자리를 화소에서 바로 읽는다. 비스듬한 view 는 같은 정보를 담아도 망이 3D 로 돌려 읽어야 하고, 지금 망에는 그럴 길이 없다(토큰마다 각도 하나만 더함 · 화소가 3D 어느 방향인지 모름).

배운 것과 다음

새 구조 m2 는 고르기는 배우지만, 비스듬한 view 에서 치수 · 자리 숫자를 읽지 못한다. 배우는 양으로는 안 풀린다.

  1. view 토큰마다 물체 기준 광선 방향(각도 + 그 토큰의 화소 자리)을 준다 — 여러 장 망들이 쓰는 꼴. 두 view 의 같은 점을 삼각 측량할 재료가 생긴다.
  2. 자리를 절대 좌표 대신 붙임(어느 몸의 어느 면에 붙나)으로 낸다 — tr182 때부터의 짐작.
  3. 그래도 안 되면 「3면도는 숫자를 바로 읽게 해 주는 꼴」 이라는 점을 되살려, view 를 받아 3면도처럼 축에 맞춘 꼴로 바꾸는 단계를 m2 앞에 둘지 사용자와 정한다.
